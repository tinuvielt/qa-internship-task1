# Тест-кейсы для API сервиса объявлений

Стенд: `https://avito.com`

Что закладывал в покрытие:
* позитивные и негативные проверки по всем ручкам;
* граничные значения (нули, отрицательные числа, пустые строки);
* проверка авторизации (отсутствующий/битый токен) и прав доступа (попытка создать объявление под чужим `sellerID` или подменить его через `X-UserId`);
* сквозной E2E-сценарий от регистрации до удаления.

---

## 1. Регистрация и авторизация

### TC-AUTH-01. Регистрация нового пользователя
* **Шаги:** отправить `POST /api/1/register` с уникальным `username` и непустым `password`.
* **ОР:** `201 Created`, в ответе вернулись числовой `id` и переданный `username`.

### TC-AUTH-02. Попытка зарегистрировать уже занятый `username`
* **Предусловие:** пользователь с таким `username` уже создан.
* **Шаги:** повторно отправить `POST /api/1/register` с тем же `username`.
* **ОР:** `409 Conflict`.

### TC-AUTH-03. Регистрация с пустыми полями или пустым телом
* **Шаги:** отправить `POST /api/1/register` с `{"username": "", "password": ""}`, затем с `{}`.
* **ОР:** `400 Bad Request`.

### TC-AUTH-04. Успешная авторизация
* **Предусловие:** пользователь зарегистрирован.
* **Шаги:** отправить `POST /api/1/autorize` с валидными `username` и `password`.
* **ОР:** `200 OK`, в ответе есть непустой `accessToken` и `tokenType: "Bearer"`.

### TC-AUTH-05. Авторизация с неверным паролем или несуществующим логином
* **Шаги:**
  1. Отправить `POST /api/1/autorize` с правильным `username` и чужим `password`.
  2. Отправить `POST /api/1/autorize` с несуществующим `username`.
* **ОР:** в обоих случаях `401 Unauthorized`.

### TC-AUTH-06. Авторизация с пустым JSON
* **Шаги:** отправить `POST /api/1/autorize` с телом `{}`.
* **ОР:** `400 Bad Request`.

## 2. Авторизация и права доступа

### TC-SEC-01. Запросы к закрытым ручкам без заголовка `Authorization`
* **Шаги:** дёрнуть без токена:
  * `POST /api/1/item`
  * `GET /api/1/item/{id}`
  * `GET /api/1/{sellerID}/item`
  * `GET /api/1/statistic/{id}`
  * `GET /api/2/statistic/{id}`
  * `DELETE /api/2/item/{id}`
* **ОР:** везде `401 Unauthorized`.

### TC-SEC-02. Запрос с невалидным Bearer-токеном
* **Шаги:** отправить `GET /api/1/{sellerID}/item` с заголовком `Authorization: Bearer invalid.token.here`.
* **ОР:** `401 Unauthorized`.

### TC-SEC-03. Создание объявления с чужим `sellerID`
* **Предусловие:** есть два зарегистрированных пользователя (User A и User B).
* **Шаги:** отправить `POST /api/1/item` с токеном User A, но в теле передать `"sellerID": <id_User_B>`.
* **ОР:** запрос отклонён (`400`, `401` или `403`), объявление под чужим пользователем не создаётся.

### TC-SEC-04. Попытка обойти проверку через заголовок `X-UserId`
* **Шаги:** отправить `POST /api/1/item` с токеном User A, чужим `sellerID` и заголовком `X-UserId: <id_User_B>`.
* **ОР:** заголовок игнорируется, сервер возвращает ошибку (`400` / `401` / `403`).

## 3. Объявления (`item`)

### TC-ITEM-01. Создание объявления с валидными данными
* **Предусловие:** пользователь авторизован.
* **Шаги:** отправить `POST /api/1/item` со своим `sellerID`, названием, ценой и блоком `statistics`.
* **ОР:** `200 OK`, в поле `status` приходит строка с UUID созданного объявления.

### TC-ITEM-02. Два одинаковых объявления получают разные UUID
* **Шаги:** два раза подряд отправить `POST /api/1/item` с одинаковыми `name`, `price`, `sellerID` и `statistics`.
* **ОР:** оба запроса успешны (`200 OK`), извлечённые UUID не совпадают (`uuid_1 != uuid_2`).

### TC-ITEM-03. Граничные значения цены и статистики
* **Шаги:**
  1. Создать объявление с `price: 0` и нулями в `statistics` (`likes: 0, viewCount: 0, contacts: 0`).
  2. Попробовать создать объявление с `price: -1`.
  3. Попробовать создать объявление с `likes: -1` (и аналогично для `viewCount` и `contacts`).
* **ОР:**
  * нулевые значения принимаются (`200 OK`);
  * отрицательные значения отклоняются (`400 Bad Request`).

### TC-ITEM-04. Пустое название и невалидный тип цены
* **Шаги:** отправить `POST /api/1/item` с `"name": ""`, затем с `"price": "free"`.
* **ОР:** `400 Bad Request`.

### TC-ITEM-05. Получение объявления по ID
* **Предусловие:** объявление создано.
* **Шаги:** выполнить `GET /api/1/item/{itemId}`.
* **ОР:** `200 OK`, вернулся массив из одного объекта, все поля (`id`, `sellerId`, `name`, `price`, `statistics`) совпадают с отправленными при создании.

### TC-ITEM-06. Получение объявления по несуществующему и кривому ID
* **Шаги:**
  1. Выполнить `GET /api/1/item/00000000-0000-4000-8000-000000000000`.
  2. Выполнить `GET /api/1/item/not-a-uuid`.
* **ОР:**
  1. `404 Not Found`
  2. `400 Bad Request`

### TC-ITEM-07. Получение всех объявлений продавца
* **Предусловие:** зарегистрирован новый пользователь без объявлений.
* **Шаги:**
  1. Вызвать `GET /api/1/{sellerID}/item`.
  2. Создать 2 объявления и снова вызвать `GET /api/1/{sellerID}/item`.
* **ОР:**
  1. `200 OK`, пустой список `[]`.
  2. `200 OK`, список из 2 объявлений с нужными ID.

### TC-ITEM-08. Запрос списка объявлений по невалидному `sellerID`
* **Шаги:** выполнить `GET /api/1/abc_invalid/item`.
* **ОР:** `400 Bad Request`.

### TC-ITEM-09. Удаление объявления и проверка повторного удаления
* **Предусловие:** объявление создано.
* **Шаги:**
  1. Вызвать `DELETE /api/2/item/{itemId}`.
  2. Вызвать `GET /api/1/item/{itemId}`.
  3. Повторно вызвать `DELETE /api/2/item/{itemId}`.
* **ОР:**
  1. `200 OK`
  2. `404 Not Found`
  3. `404 Not Found`

## 4. Статистика (`statistic` v1 и v2)

### TC-STAT-01. Получение статистики v1 и v2 по существующему объявлению
* **Предусловие:** создано объявление со статистикой `{"likes": 21, "viewCount": 11, "contacts": 43}`.
* **Шаги:** выполнить `GET /api/1/statistic/{itemId}` и `GET /api/2/statistic/{itemId}`.
* **ОР:** обе ручки возвращают `200 OK`, значения `likes`, `viewCount`, `contacts` совпадают с исходными.

### TC-STAT-02. Статистика v1 и v2 для несуществующего и невалидного ID
* **Шаги:** запросить статистику v1 и v2 для `00000000-0000-4000-8000-000000000000` и для `invalid-uuid`.
* **ОР:** `404 Not Found` для несуществующего UUID и `400 Bad Request` для невалидного формата.

---

## 5. E2E-сценарий

### TC-E2E-01. Полный цикл жизни объявления
* **Шаги:** регистрация -> авторизация -> создание объявления -> чтение по ID -> проверка в списке продавца -> проверка статистики v1 и v2 -> удаление -> проверка `404` при повторном чтении.
* **ОР:** каждый этап проходит без ошибок, после удаления объявление недоступно.
